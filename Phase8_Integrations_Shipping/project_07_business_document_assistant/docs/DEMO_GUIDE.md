# Presenter guide

## Message to the audience

“Product owners should spend their time deciding what the business needs. This workspace organizes raw notes, relevant policy, a consistent document template, and human review. It produces a Word document or a Confluence-style page. Today we use existing Copilot through a manual handoff; this is not an autonomous Copilot backend.”

## Prepare

- Run the app and `python demo.py` using the project README.
- Open Word or a compatible DOCX viewer before the meeting.
- Use only the bundled fictional Northstar Workshop room-booking example.
- Choose a fresh browser session for an empty document history.
- Have `outputs/brd-sample-response.json` available for a no-network import demonstration. Explicitly describe it as a fixture if used.
- Keep `outputs/brd.docx` and `outputs/brd.html` as a fallback if the live demo environment fails.

## Ten-minute walkthrough

| Time | Action | What to explain |
|---|---|---|
| 0:00–1:00 | Show the input screen and Load sample | A product owner provides notes; no Git commands, Jenkins jobs, or MCP configuration. |
| 1:00–2:00 | Open the sample source excerpts | Business rules are separate from meeting proposals; citations include page versions. These are fictional snapshots, not live retrieval. |
| 2:00–3:00 | Prepare Copilot brief | The template and context travel together into the employee's approved Copilot interface. No shared token or inferred backend entitlement. |
| 3:00–4:00 | Run Copilot manually or show the saved fixture | The handoff is visible. Never describe fixture text as generated by Copilot. |
| 4:00–5:00 | Import JSON; show citation validation | The app checks section shape and source IDs. It cannot prove factual grounding. |
| 5:00–6:00 | Discuss 30 versus 14 days | Proposed policy changes require a decision. The tool surfaces the disagreement instead of silently choosing. |
| 6:00–7:00 | Edit and save; download Word | A working draft becomes a reusable deliverable with source provenance. |
| 7:00–8:00 | Review, approve, simulate publication | The destination is shown before confirmation. No actual Confluence page is created. |
| 8:00–9:00 | Edit again; show approval invalidation | Approval applies to a specific revision; old publication content remains intact. |
| 9:00–10:00 | Discuss adoption path | Templates and useful context come first; SSO, Confluence permissions, and an approved AI integration enable wider rollout. |

## Questions worth demonstrating

- What happens if a selected source is omitted from the imported rules section? Import fails with a corrective message.
- What happens if a user cites `[S99]`? Import rejects the unknown citation.
- Can we publish before approval? The UI disables it and the server rejects it.
- Can an old approval authorize edited content? No; save creates a new revision and clears approval.
- Can a second browser session read the first session's document URL? The server returns 404.
- Will the tool catch every conflicting business rule? No. Offline detection is intentionally narrow; Copilot output also needs review.
- Does a green approval badge mean all open questions are resolved? No. It records a local review acknowledgment, not enterprise sign-off or policy-owner authorization.

## Known limitations to say aloud

This demo does not implement SSO, live Confluence retrieval/publishing, automatic Copilot invocation, a model API, semantic verification, rich Word templates, or production deployment. It demonstrates the product workflow and the contracts needed to add those capabilities.

## Demo acceptance checklist

- [ ] All three document types produce distinct heading structures.
- [ ] Copilot brief includes selected sources only, exact template headings, and original notes.
- [ ] Imported response can be reviewed and edited.
- [ ] Word export opens and contains the latest saved revision.
- [ ] Notes and page references are visible in the generation record.
- [ ] Policy disagreement remains a question until a human decides.
- [ ] Publication requires current approval and clearly stays local.
- [ ] Saved edits revoke approval and do not overwrite a published snapshot.

## Feedback to collect

Ask product owners which template sections need the most editing, how often the context selection is wrong, whether Copilot's JSON handoff is manageable, what Word styling is mandatory, and whether their preferred final destination is Word or Confluence. Measure time from notes to a reviewed draft, not merely time to first generation.
